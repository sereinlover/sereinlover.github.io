# 第 7 章 总结与展望

先用一张表回顾整条流水线：

| 层            | 回答什么问题        | 主要方法                    | 输出                             | 章节    |
| ------------ | ------------- | ----------------------- | ------------------------------ | ----- |
| L1 声学特征层     | 这段声音的形状       | librosa、Essentia 的确定性计算 | FeatureBundle / FeatureSummary | 第 3 章 |
| L2 音乐理解层     | 这段音乐的内容       | 预训练模型推理 + 经典信号处理        | UnderstandingBundle            | 第 4 章 |
| L3 美学评分层     | 在四个维度上的表现     | 确定性公式：归一化、加权求和          | AestheticBundle                | 第 5 章 |
| L4 AI 解读层 | 怎么翻译成用户能读懂的文字 | 大模型 + 工具调用循环            | AnalysisResult                 | 第 6 章 |

L1 到 L3 由固定的算法、参数或预训练模型得出数值结果。L4 是流程中唯一调用大语言模型的环节，根据这些结果生成文字解释。

## 7.1 已知局限

这一节从四个方面汇总项目的局限。

| 类别 | 影响范围 | 能不能靠调参数解决 |
|---|---|---|
| 评分框架的覆盖范围 | 所有歌的四维分数 | 不能，是指标定义的问题 |
| 评分尚缺听众验证 | 分数与听感的一致程度 | 需要独立的听众实验 |
| L2 各模块的能力边界 | 某些类型的歌 | 大多不能，受限于预训练模型 |
| 工程上的取舍 | 速度、部署、可维护性 | 可以，但有代价 |

AI 解读的校验范围见第 6.3、6.5 节，提示词能约束的内容见第 6.4 节。

### 安静与独奏作品的低分倾向

这是整个项目最大的局限。它来自四维框架本身的覆盖范围。

在测试组的歌曲里，巴赫《G 弦上的咏叹调》的情感深度得分为 21.5，活力张力得分为 23.3，均为本次测试中的最低分。巴赫十二平均律前奏曲的物理精确性得分为 44.0，肖邦夜曲 Op. 9 No. 2 的活力张力得分为 26.8。这几首作品在部分维度上得分偏低。

物理精确性和活力张力中的三个子指标分别衡量频带间的能量分布、段落间的强弱变化和起音强度峰值的密度。安静或编制较少的作品更容易在这些指标上得分偏低，具体原因见下表。

| 子指标 | 为什么对安静、独奏作品不利 | 章节 |
|---|---|---|
| 物理精确性的频率均衡度 | 独奏乐器的能量天然集中在一个窄频段，低、中、高三组频带差距大 | 5.2 |
| 活力张力的跨段落动态对比 | 连续克制的旋律线，各段的平均响度很接近，对比接近 0 | 5.5 |
| 活力张力的起音爆发密度 | 起音变化较缓时，满足筛选条件的峰值可能较少 | 5.5 |

情感深度也会间接不利：情绪平稳的作品，弧线起伏小，得分自然低（5.4）。这本身符合这个维度的定义，但和前三项叠加在一起，安静的作品会在四个维度里有三个同时偏低。

这些低分需要结合指标的测量范围来理解。物理精确性考察拍速稳定性、动态范围和频率均衡度，活力张力考察段落间的强弱反差和起音强度峰值的密度。第 1.3 节提到的《G 弦上的咏叹调》就是一个例子。它在活力张力上的得分反映了录音中测得的强弱变化和起音活动，作品中克制与留白的表达效果仍需结合具体的音乐语境来判断。

调整参照值可以改变频率均衡度的分数分布，但该指标衡量的仍是低、中、高三个频段之间的能量差异。若要评价克制与留白的表达效果，需要先明确哪些特征能反映这种表达，再通过人工评估检验指标是否符合听众的判断。项目目前尚未建立相应的测量方法。

现有样本还不足以判断，低分主要与独奏编制有关，还是与作品较少出现强弱变化有关。后续可选用强弱对比明显的独奏录音，例如莫扎特的《土耳其风回旋曲》或肖邦的《革命》练习曲，再与较平稳的独奏录音比较。

### 响度和节奏密度对情感深度得分的影响

在 EDM 曲目的测试中，deadmau5 的曲目在情感深度上得到 23.5 分，《One Mind》得到 74.4 分，Daft Punk 的《Harder, Better, Faster, Stronger》得到 84.6 分（第 5.4 节）。

这个维度根据效价和唤醒度曲线计算。EDM 中逐渐增强的响度和节奏密度可能推高模型估计的唤醒度，从而让分数高。项目曾尝试降低此类变化对评分的影响，但《Art of Life》中与渐强相关的变化也会同时被削弱。现有指标难以区分不同音乐因素对唤醒度的贡献，因此项目保留了评分公式，并在系统提示词中要求模型把此类高分解释为测得的唤醒度变化（第 6.4 节）。

### 段内高潮的测量局限

肖邦夜曲 Op. 9 No. 2 的跨段落动态对比为 0.037。其中一个段落出现了明显的渐强，段内峰值约为其他段落的两到三倍。由于这个指标比较的是各段的平均响度，渐强对段落均值的影响有限（第 5.5 节）。

项目曾用全曲 RMS 最大值减去各段平均 RMS 的中位数，尝试捕捉段内高潮。采用这一算法后，一首 Lofi Hip Hop 曲目因孤立的响度峰值达到 0.587，高于《Forever Love》的 0.386，因此项目未采纳该算法。后续可以测试按连续多帧的响度变化来识别高潮。

### 常规和声与规整段落对结构逻辑得分的影响

巴赫十二平均律前奏曲的 T-S-D 覆盖率为 0.853，一首 Lofi Hip Hop 曲目的覆盖率为 0.812，《Art of Life》则为 0.535（第 5.3 节）。

覆盖率衡量识别出的和弦事件与当前调的主、下属、属和弦清单的匹配程度。项目对全曲采用同一个调，转调之后的和弦仍按原调清单判断，因此覆盖率可能降低。段落均衡度则反映段落时长是否接近。解读结构逻辑分数时，需要同时考虑这两项的测量范围和和弦丰富度。

### 参照值的适用范围

本项目作为实验项目，只根据有限曲目的观测结果设定部分参照值（第 5.1 节）。后续若要让同一套参照值用于更广泛的作品，可以扩大校准曲目集，使其覆盖目标风格、编制和制作条件，再根据观测分布设定参照值，例如使用预先选定的高百分位数。

如果目标是比较同一流派内的作品，也可以为各流派分别设定参照值。各流派的校准曲目需要覆盖该流派内的编制和动态差异，分数也应在相应流派内解读。

上述两种做法都需要用未参与校准的曲目验证。

参照值会影响得分的分布。评估参照值时，需要同时查看原始值的分布、曲目间的排序和得分触及上限的情况。

### 评分与听感的一致性尚待验证

第 5 章的经验参照值和权重通过比较曲目的观测值与评分排序来校准。对照实验也事先设定了对部分曲目的预期，但这些预期来自开发者的判断。要评估这些指标与听感的一致程度，还需要独立的听众评价。

所以，这套分数和人听到音乐时的真实感受有多大的相关性，目前没有任何数据支持。要回答这个问题，需要找一批听众，对同一批歌做独立的评判，再看系统的分数和人的评判是否一致。第 7.2 节介绍了成对比较的做法。

L2 的部分任务有外部标注可供对照。情感回归报告了与 PMEmo 人工标注的相关系数（第 4.2 节），乐器识别报告了 MTG-Jamendo 上的精确率与召回率（第 4.3 节），结构边界在 Sargon 上评估了 F 值（第 4.4 节）。L3 的四维评分尚未用听众判断做过对应验证。

### L2 音乐理解的适用范围

L2 的每个模块，都有一部分音乐处理不好。这些局限大多来自预训练模型本身的训练数据，项目能做的只是如实记录：

| 模块    | 局限                                               | 原因                                  | 章节  |
| ----- | ------------------------------------------------ | ----------------------------------- | --- |
| 流派识别  | 听感本身模糊的歌会判错：Bee Gees 的迪斯科被判成浩室，《Billie Jean》没进前三 | 歌曲的编曲底子本身就跨流派；不同模型的盲区互不重叠           | 4.1 |
|       | 界面上的置信度是 15 个大类之间的相对占比，不是模型的原始概率                 | 模型是多标签的 sigmoid 输出，展示时做了归一化         | 4.1 |
| 情感回归  | 唤醒度在 PMEmo 上的相关系数是 0.52，比官方的 0.773 低不少           | 换了数据集，标注者和评分习惯不同                    | 4.2 |
| 乐器识别  | 小号、单簧管、竖琴、圆号等管弦乐乐器几乎识别不出来                        | 单乐器样本的分数仍偏低，改变分段长度未能改善这一结果            | 4.3 |
|       | 阈值偏向精确率，会漏掉一些真实存在的乐器                             | 有意的取舍：误报会被 L4 当作证据引用，代价更大           | 4.3 |
|       | 不识别人声                                            | 人声类别的精确率和召回率都太低，已经排除                | 4.3 |
| 结构分段 | 时长缩放尚未针对 1 到 5 分钟的曲目单独验证 | 验证覆盖了短片段、Sargon 曲目和《Art of Life》。见 [结构分段实验记录](../computable-beauty/doc/steps/engine-l3-mir.md) | 4.4 |
|       | 响度差异可能让同类段落被分到不同组 | 单位向量归一化与 z-score 处理后的两个特征在距离中的贡献可能不同 | 4.4 |
|       | 最后一遍副歌升调，会被判成尾奏                                  | 升调后 chroma 和前面的副歌对不上，又恰好是最后一段       | 4.4 |
| 和弦识别 | 只识别大、小三和弦，其他和弦可能被归入已有类别 | madmom 的 majmin 词表只有 24 个和弦类别 | 4.5 |
|       | 没有做过量化评估                                         | 找不到同时有音频和和弦标注、没有版权限制的公开数据集          | 4.5 |
| 拍号检测  | 只能区分 3/4 和 4/4                                   | 训练数据以 3、4 拍为主；6/8 听感是 2 拍；DBN 假设拍等距 | 4.6 |
|       | 节拍自由、装饰音多的音乐会作品，即使是标准的 3/4 也会误判                  | 部分录音的强拍信号不够明确，测试中出现过误判              | 4.6 |
| 张力与释放 | 测的是声学粗糙感，不是乐理上的和声紧张度；失真音色会抬高张力                   | 感官不协和度模型只看频谱峰值之间的距离                 | 4.7 |
|       | 张力在不同歌曲之间区分度不高                                   | 真实曲目的平均不协和度跨度很窄                     | 4.7 |

### 处理耗时、缓存与部署

- **长曲目的分段耗时**：29 分钟的曲目，结构分段冷启动要 150 到 215 秒，最大的开销是谐波/打击乐分离。特征缓存放在调用时创建的临时目录里，重复分析时需要重新计算（第 4.4 节）。评估过两个提速方向：给特征提取降采样（需要重新验证边界检测的准确率），按 `audio_id` 恢复隔离的缓存（只对重复分析有用），权衡后暂时没有做。但是 Gateway 有分析结果的缓存，同一首歌第二次上传会直接返回已有结果，不会重新计算。
- **Engine 镜像架构**：项目只发布 `linux/amd64` 的 Engine 镜像，其在 ARM64 主机上的运行依赖主机提供的 x86-64 模拟。Gateway 和 Web 同时发布 amd64 和 ARM64 镜像（第 3.8 节）。
- **L1 的重复计算**：L1、L2、L3 三个接口各自在内部跑一遍 L1，因此 Engine 无需在请求之间保存逐帧特征（第 3.11 节）。
- **切换语言后的重新分析**：分析结果的缓存键里带着语言，同一首歌第一次用另一种语言分析时，L1 到 L4 都会重新计算，而 L1 到 L3 的结果其实和语言无关（第 1.4 节）。

## 7.2 应用方向

### 用分析结果辅助编写生成提示词

第 1.3 节提出了这个项目的一个应用设想：用结构化的分析结果辅助描述参照音乐，再结合文字 Prompt，引导 AI 生成音乐。

用文字提示词生成音乐时，可以写"悲伤又克制的钢琴曲"。如果没有参照曲目，文字本身很难描述清楚希望保留的节奏、配器或强弱变化。

Computable Beauty 提供了另一种描述方式。分析一首参照曲目，得到的不是几个形容词，而是一组有具体数值的维度。以《Forever Love》为例：

| 描述 | 来自 | 数值 |
|---|---|---|
| 拍速稳定 | L1 拍速稳定性 | 拍间隔标准差 0.03 秒 |
| 较响与较轻部分的差距 | L1 动态范围 | 24.68 dB |
| 推动感强 | L3 活力张力的爆发密度 | 每分钟 279 次 |
| 段落之间有明显的安静—爆发对比 | L3 活力张力的动态对比 | 0.26 |
| 情绪有几次幅度不小的转折 | L3 情感深度 | 效价落差 0.67，全曲 8 次极性切换 |
| 钢琴和弦乐、忧郁感伤 | L2 乐器和情绪标签，主奏声部需回听判断 | — |

L4 可以参考这些数字生成文字解读。第 1.3 节展示过将《Forever Love》的分析结果整理成 Suno Prompt 的例子，例如用"段落之间有明显的强弱对比"描述动态对比，用"在部分位置出现明显的情绪转向"描述模型检测到的情绪变化。这些文字是对指标的概括，仍需要结合原始数据和实际听感核对。

相比只写"悲伤又克制"，分析结果可以为描述提供更多可讨论的维度。例如，想要推动感更弱一些，可以调整 Prompt 中"节奏具有持续的推动感"这一描述。这样的调整是否能让生成结果更接近预期，还需要通过实验验证。

### 用分析结果描述影视临时配乐

这个用途有一个真实的行业需求作为依据。影视行业有 temp track（临时配乐）的惯例：制作方会找一首"感觉对"的现成曲目交给作曲家时说"大概要这种感觉"。

问题在于，"这种感觉"很难准确传达。作曲家要反复揣摩：到底是喜欢它的节奏、配器、和声，还是情绪的走向？如果用 AI 生成配乐，这个问题同样存在。

把 temp track 用 Computable Beauty 分析一遍，"这种感觉"就被拆成了可以逐项讨论的维度：是活力张力高，还是情感深度高；是动态对比强，还是起音密集。沟通可以从"大概这种感觉"，变成"活力张力要接近这首，但情感深度可以再高一些"。

实测结果展示了这种拆解能看出哪些差异。《Forever Love》靠活力张力突出，《Art of Life》靠情感深度突出，《Symphonie Fantastique》靠物理精确性和结构逻辑突出。同样是"打动人的音乐"，打动的方式不一样。四个维度独立展示、不合成总分，能让这种差异能被看见。

### 为音乐生成提供结构化输入

更进一步，分析结果本身是一份结构化的数据，可以直接作为 AI 音乐生成系统的输入，而不必先转换成文字。

比如一个生成系统，可以接收"目标 BPM 120、拍号 4/4、调性 D 小调、和弦进行 Dm-Bb-F-C、段落结构为前奏—主歌—副歌—主歌—副歌—尾奏、情感弧线在副歌处唤醒度上升"这样的参数。L1 和 L2 的输出，恰好覆盖了其中大部分字段：

| 生成参数 | 对应的分析字段 | 章节 |
|---|---|---|
| 速度 | `bpm` | 3.7 |
| 调性 | `key` | 3.8 |
| 拍号 | `signature` | 4.6 |
| 和弦进行 | `chords`，带起止时间 | 4.5 |
| 段落结构 | `structure`，带起止时间和类型 | 4.4 |
| 情绪走向 | `emotion_arc`，每约 1.5 秒一个点 | 4.2 |
| 配器 | `instruments` | 4.3 |
| 风格 | `genre_top3` | 4.1 |

这个方向需要生成模型本身支持这类结构化的条件输入，目前只是一个设想。但它说明了 L1 到 L3 的价值不只在于"打分"：它们把一首歌拆解成了一组生成系统可能用得上的音乐参数。

### 应用落地前的验证与改进

要让这些应用真正可用，有几个局限需要先解决。按优先级排列：

1. 评分能否用于描述参照音乐，首先取决于它与听众判断的一致程度。

   可以请听众做**成对比较**。每次播放两首歌，请听众选出张力更强的一首。这样，听众只需判断同一对曲目之间的差别，无需自行定义 70 分和 80 分各代表怎样的张力。

   有了大量成对比较的结果，可以用 Bradley-Terry 一类的统计方法，反推出每首歌在"张力"上的排序。再看系统的活力张力分数排出来的顺序，和这个排序是否相关，就能检验这个维度到底是否能量化人的感受。

2. 从 AI 解读整理生成提示词时，指标含义的误读可能被带入后续描述。第 6.5 节列出了三项改进方向。

   - 在工具里提取解释中的所有数字，与允许引用的上下文数值核对，并处理单位换算与取整。
   - 把模型提交的分数、证据，和 L3 的原始值直接比较。
   - 在上下文里为每个证据字段附上一句定义，让模型不必从字段名猜含义。

   第三个改进针对的，正是第 1.3 节解读里那两个误读。

3. 扩大校准曲目集，并用独立曲目复核参照值。面向同一流派内的比较时，可评估按流派分别校准的效果（第 7.1 节）。

4. 后续还可以在追问的提示词中补充指标方向的约束，并加入强弱对比明显的独奏录音，分别检查编制和动态变化的影响。

前两项决定了这个系统能不能被信任，后两项决定了它在更多类型的音乐上表现如何。

## 7.3 项目复盘

第 1.1 节写到，我想做一个完整的项目，把数字信号处理、音频特征、乐理和机器学习等知识串起来。回头看，这个项目开发完成，并写成文章复盘后，可以更清晰地看到哪些判断被验证是对的，哪些认知在做的过程中被修正了。

### 经过实践检验的设计选择

#### 先搭通完整流程

开发初期，项目用占位数据搭通 Engine、Gateway 和 Web 之间的流程，并接入 L4 的工具调用循环。随后，逐层将 L1 至 L3 的占位结果替换为实际计算。每替换一层，都可以在结果页检查新结果对整体分析的影响。

#### 用目标数据检验模型和阈值

第 4 章记录了模型和阈值在目标数据上的三组检验结果。

- DEAM 情感模型官方报告的唤醒度相关系数是 0.773，在 PMEmo 上实测为 0.52（第 4.2 节）。
- 在 GTZAN 上训练的 CNN，测试集 F1 为 0.63，在另行挑选的曲目上识别表现明显下降（第 4.1 节）。
- 乐器识别比较了不同阈值下的精确率和召回率，最终将阈值从 0.15 调整为 0.35（第 4.3 节）。

#### 复用已有工具和模型

调性检测使用 Essentia，和弦识别使用 madmom，结构分段使用 MSAF，流派、乐器和情感分析使用 Essentia 的预训练模型。复用这些方案减少了独立实现算法和训练模型的工作量。

#### 锁定依赖的提交版本

项目开发时，MSAF 和 madmom 的 PyPI 发布版在所用环境中遇到了安装问题，两者的 GitHub 主分支已有相关修复。项目验证了可用版本，并在依赖配置中锁定了对应的提交。

#### 让 Engine 独立处理每次请求

L1 特征在三个接口内分别提取（第 3.11 节），追问则按每次请求重建上下文（第 6.6 节）。这种设计便于独立测试各个接口，也便于重启服务。一次完整分析会重复提取 L1 特征，追问也需要调用方提供相关上下文。

### 测试中修正的判断

#### 明确评分指标的测量范围

项目的四个维度描述的是选定的音乐特征，例如拍速稳定性、常见和弦的覆盖率、情感曲线的变化和段落间的动态对比。留白、克制或和声转折在作品中的表达效果，仍需结合音乐语境理解（第 1.3 节、第 7.1 节）。

#### 用独立曲目复核模型表现

早期流派模型在 GTZAN 测试集上的 F1 为 0.63，在独立选取的真实曲目上识别表现较弱。此后，项目把目标场景中的独立测试纳入模型选择（第 4.1 节）。

#### 用量化结果检验提示词

初步抽查曲目时，我曾怀疑 CLAP 的提示词 `"This is a {genre} music track"` 会引入偏差。在 GTZAN 上比较后，这一写法的 F1 高于 `"{genre} music"`。初步抽查可以提出假设，比较提示词的整体表现还需要更广的测试（第 4.1 节）。

#### 用原始数据定位异常结果

有些数值处于设计范围内，曲目间的排序仍与预期不符。测试中出现过以下情况。

- 按全曲平均 RMS 衡量能量感时，一首儿歌排到第三，高于一些全编制的摇滚曲目。见 [L2 模块实验记录](../computable-beauty/doc/steps/engine-l2-classifiers.md)。
- 以全曲逐帧 RMS 的极差衡量动态对比时，一首 Lofi Hip Hop 曲目排在首位。见 [L3 评分实验记录](../computable-beauty/doc/steps/engine-l3-scoring.md)。
- 儿歌的结构逻辑得分与《Forever Love》接近（第 5.3 节）。

把这些曲目的结果放在一起比较，可以发现只检查得分是否触及上限时容易遗漏的问题。对照原始曲线、分段结果和子指标的分数贡献后，项目修正了对几项异常结果成因的判断。

- 《小星星》的物理精确性排序一度被认为与权重有关。拆开子指标后发现，曲末淡出拉高了动态范围。现行的首尾裁剪规则见第 3.9 节，排查过程见 [L3 评分实验记录](../computable-beauty/doc/steps/engine-l3-scoring.md)。
- 《G 弦上的咏叹调》的活力张力偏低，一度被怀疑是弦乐起音检测所致。检查发现，288 秒内检测到了 544 个峰，低分主要来自段落间的平均响度差异较小（第 5.5 节）。
- 《小狗圆舞曲》的拍号误判一度被归因于编曲版本。管弦乐版和钢琴独奏版都出现了误判，项目随后将注意力转向拍点和强拍的规整程度。见 [L2 模块实验记录](../computable-beauty/doc/steps/engine-l2-classifiers.md)。

#### 根据验证结果和实现成本取舍功能

- **综合美学指数。** 四个维度的相对权重缺乏统一依据，最终独立展示四个维度（第 5.1 节）。
- **自行训练的流派 CNN。** 模型在 GTZAN 上达标，在独立曲目上的表现较弱，最终采用预训练模型（第 4.1 节）。
- **人声识别。** 评估过的两种方案表现均不理想，因此结果中省去人声标签（第 4.3 节）。
- **ONNX 加速。** 在 Go 中推理需要复现 Essentia 的预处理，并验证转换前后的输出一致性。项目评估了它对整条分析流程的提速作用，最终保留 Essentia 推理，通过结果缓存减少重复分析。

### 项目给我的收获

Computable Beauty 最初的灵感来自我听《Art of Life》时的感受。做完这个项目后，我可以让提问更具体一些。比如，我听到的情绪转折出现在什么位置？可以先看情感弧线在哪些时刻出现明显变化，再回听相应的段落，核对模型估计的变化与自己的听感是否一致。至于这些转折为什么打动我，还要回到作品的编曲和演奏中理解。

在从软件开发和后端开发转向音乐科技的过程中，这个项目让我把信号处理、音频特征分析、乐理和机器学习用到同一套系统里。现在，我可以从结果页上的一个分数追溯到参与计算的特征和公式，也可以用原始数据核对模型写出的解释。当分析结果与听感有出入时，我知道可以从哪里开始检查不一致的原因。

## 7.4 本章小结

Computable Beauty 实现了从音乐音频分析到四维评分和文字解读的流程。项目测试揭示了几个需要继续验证的问题，包括评分对安静、编制较少的作品是否存在偏差，情感深度在多大程度上受响度变化影响，以及模型解读能否准确说明数值的含义。

后续可通过听众的成对比较检验评分与听感的一致程度，同时加强解读与原始证据的对照。参照值可以用覆盖更广的曲目集复核，也可以进一步检验按流派分别校准是否适合流派内比较。至于将参照曲目的分析结果用于音乐生成的更广阔应用，需要通过独立实验检验它是否能使生成结果更接近预期。
