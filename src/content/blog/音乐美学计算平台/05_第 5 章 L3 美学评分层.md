# 第 5 章 L3:美学评分层

L1 测出了声音的物理特征，L2 判断出了音乐的内容。L3 要做的，是把这些结果转换成四个 0 到 100 的分数，回答第 1.3 节提出的问题：这首曲子在四个层面上表现如何。

| 维度 | 对应第 1.3 节的层面 | 衡量什么 |
|---|---|---|
| 物理精确性 | 物理层 | 节奏稳不稳、强弱层次够不够、频率分布均不均衡 |
| 结构逻辑 | 结构层 | 和声用得多规范、段落安排多整齐、和声素材多丰富 |
| 情感深度 | 情感层 | 情绪曲线起伏多大、转折多频繁 |
| 活力张力 | 活力层 | 段落之间的强弱对比、起音活动的密集程度 |

L3 的每个分数都由几个**子指标**加权组成，每个子指标都是从 L1、L2 的结果直接算出来的数值。

## 评分接口的输入与输出

L3 的代码在 `apps/engine/scoring/` 下，每个维度一个文件，加一个共用的工具文件：

| 文件 | 内容 | 用到的输入 |
|---|---|---|
| `_util.py` | 两个共用函数 `normalize`、`dimension_score` | — |
| `physical_precision.py` | 物理精确性 | L1 的 `tempo_stability`、`dynamic_range_db`、`mel_spectrogram` |
| `structural_logic.py` | 结构逻辑 | L1 的 `key` + L2 的 `chords`、`structure` |
| `emotional_depth.py` | 情感深度 | L2 的 `emotion_arc` |
| `vital_tension.py` | 活力张力 | L1 的 `rms`、`onset_strength` + L2 的 `structure` |

评分使用 L1 的六项声学特征、采样率和音频时长，以及 L2 的和弦、段落和情感弧线。流派、乐器、情绪标签、张力、释放和能量感用于结果展示及解读。

对外的接口是 `/internal/score-aesthetics`，实现在 `routers/analysis.py: score_aesthetics`：

```python
def score_aesthetics(payload: ScoreAestheticsRequest) -> AestheticBundle:
    # FeatureBundle's time-series arrays never cross the service boundary (see
    # contracts/contracts/types.py), so payload.feature_summary can't carry them —
    # re-extracted here from audio_path instead, same pattern L2's classifiers use.
    fb = extract_feature_bundle(payload.audio_id, payload.audio_path)
    ub = payload.understanding

    physical_precision = score_physical_precision(fb)
    structural_logic = score_structural_logic(fb, ub)
    emotional_depth = score_emotional_depth(ub)
    vital_tension = score_vital_tension(fb, ub)

    return AestheticBundle(
        audio_id=payload.audio_id,
        physical_precision=physical_precision,
        structural_logic=structural_logic,
        emotional_depth=emotional_depth,
        vital_tension=vital_tension,
    )
```

两个输入的来源不同：

- **L1 的结果在接口内部重新计算。** 评分要用 RMS、mel 频谱这些时间序列，它们不能跨服务传输，Gateway 传过来的 FeatureSummary 里没有，所以接口内部重新跑一遍 L1（第 3.11 节）。
- **L2 的结果由 Gateway 传进来。** 请求体里的 `understanding` 是 L2 接口返回的 UnderstandingBundle，L3 直接用。L2 的结果都是列表和数，可以放进 JSON 传输。

四个评分函数互相独立，各自返回一个 `DimensionScore`，组装成 `AestheticBundle` 返回。结果页的"美学分析"标签页显示这四个分数和各自的证据值，LLM 也会拿到全部内容（第 6.4 节）。

## 四个评分维度及其子指标

先把四个维度的全部子指标列在一起，后面各节逐个解释：

| 维度 | 子指标 | 权重 | 原始值 | 参照值 | 方向 |
|---|---|---|---|---|---|
| 物理精确性 | 节奏稳定性 | 0.4 | 拍间隔标准差（秒） | 0.13 | 越小越好 |
| | 动态范围 | 0.3 | 动态范围（dB） | 5 到 25 | 越大越好 |
| | 频率均衡度 | 0.3 | 三组频带的标准差（dB） | 25 | 越小越好 |
| 结构逻辑 | T-S-D 覆盖率 | 0.3 | 落在和声功能清单里的和弦比例 | 不需要 | 越大越好 |
| | 段落均衡度 | 0.3 | 段落时长的变异系数 | 2.0 | 越小越好 |
| | 和弦丰富度 | 0.4 | 不同和弦的种类数 | 24 | 越大越好 |
| 情感深度 | 效价落差 | 0.4 | 效价最大值减最小值 | 1.0 | 越大越好 |
| | 唤醒度离散 | 0.3 | 唤醒度的标准差 | 0.15 | 越大越好 |
| | 极性切换率 | 0.3 | 效价正负切换次数除以相邻点的间隔数 | 0.025 | 越大越好 |
| 活力张力 | 跨段落动态对比 | 0.5 | 最响和最轻段落的平均 RMS 之差 | 0.29 | 越大越好 |
| | 起音爆发密度 | 0.5 | 每分钟符合条件的起音强度峰数 | 310 | 越大越好 |

本章用两首歌做完整的计算示例：

- **《Forever Love》**：第 1.3 节引用的 AI 解读对应的音乐。
- **`sample.mp3`**：第 3、4 章一直在用的 30 秒咏叹调。

## 5.1 通用评分流程

四个维度的公式各不相同，但都遵循同一个模板（第 2.9.4 节）：

1. 按各指标的公式，把原始值换算为 0 到 1 的子分数。需要按参照值换算时，把结果限制在这一范围内。覆盖率本身就在 0 到 1 之间，可以直接使用。
2. 原始值越小得分越高的指标，用 1 减去换算结果，统一子分数的方向。
3. 将子分数按权重相加，再乘以 100，得到该维度的得分。

以活力张力为例，《Forever Love》的两个原始值是动态对比 0.26、爆发密度每分钟 278.93 次：

$$
\begin{aligned}
\text{动态对比子分数} &= 0.26 / 0.29 \approx 0.90 \\
\text{爆发密度子分数} &= 278.93 / 310 \approx 0.90 \\
\text{活力张力} &\approx (0.5 \times 0.90 + 0.5 \times 0.90) \times 100 = 90
\end{aligned}
$$

### normalize:按参照值换算并截断

`_util.py` 中的 `normalize` 负责按参照值换算并截断：

```python
def normalize(value: float, reference_max: float) -> float:
    """Scales value into [0,1] relative to an expected maximum, clipping
    outliers instead of letting them blow past 1 (or below 0)."""
    return float(np.clip(value / reference_max, 0.0, 1.0))
```

`np.clip` 把结果限制在 0 到 1 之间：超过参照值的，记为 1；小于 0 的，记为 0。

### 反向指标的计分

有的子指标越大越好，比如动态范围、和弦种类数；有的越小越好，比如拍间隔的波动、段落时长的变异系数。越小越好的，代码写成 `1.0 - normalize(...)`。

反转之后，所有子分数都是"越大越好"，才能直接加在一起。

### 子分数的加权求和

每个维度内部的权重加起来都等于 1，所有子分数都是满分时，维度分数正好是 100（第 2.9.4 节）。

权重体现的是"哪个方面更重要"的判断。项目的做法是先按设计意图给出初始值，再在一批真实歌曲上检查排序是否符合直觉，发现明显不合理时再调整。

### 参照值的校准

参照值决定原始指标怎样换算成 0 到 1 的子分数。这个实验项目使用有限曲目的观测结果设定部分参照值，作为当前版本的计分基准。

对于直接按比例计分的指标，设原始值为 $x$、参照值为 $R$，子分数就是 $x / R$ 截断到 0 到 1 后的结果。项目选取一个较高的校准观测值 $x_0$，希望它对应到约 0.9，因此取 $R = x_0 / 0.9$。0.9 是设定的换算目标，为比 $x_0$ 更高的取值留出得分空间。

下表列出了几项参照值的依据。反向计分和设有上下限的指标，按各自的公式换算。

| 子指标 | 当前参照值或区间 | 校准所用的观测值 | 对应的子分数 |
|---|---|---|---|
| 节奏稳定性 | 0.13 秒 | 巴赫独奏的拍间隔标准差为 0.013 秒 | $1 - 0.013 / 0.13 = 0.90$ |
| 动态范围 | 5 到 25 dB | `sample.mp3` 在校准时测得 23.2 dB | $(23.2 - 5) / (25 - 5) = 0.91$ |
| 频率均衡度 | 25 dB | 校准曲目的三组频带标准差为 8.8 到 14.2 dB，据此适度放宽参照值 | 约 0.43 到 0.65，按 $1 - \text{标准差} / 25$ 计算 |
| 效价落差 | 1.0 | 《Art of Life》的效价落差约为 0.92 | $0.92 / 1.0 = 0.92$ |
| 唤醒度标准差 | 0.15 | 《Art of Life》的唤醒度标准差为 0.135 | $0.135 / 0.15 = 0.90$ |
| 段落均衡度 | 2.0 | 《G 弦上的咏叹调》的段落时长变异系数约为 0.37 | $1 - 0.37 / 2.0 \approx 0.82$ |

表里的 23.2 dB 是确定动态范围上限时用的测量值。按现行的首尾裁剪方法（第 3.9 节），`sample.mp3` 测得 11.87 dB。评分区间仍是 5 到 25 dB，因此当前的动态范围子分数约为 0.34。

换一批校准曲目，观测到的高值和取值范围可能不同。参照值在其他曲目上是否适用，需要用未参与校准的曲目复核。扩大校准曲目集与按流派分别设定参照值的条件见第 7.1 节。

### dimension_score:输出分数与证据

每个维度最后都调用同一个函数，把结果打包：

```python
def dimension_score(score: float, evidence: dict[str, float]) -> DimensionScore:
    """Rounds score/evidence to 2 decimals before they leave L3 — evidence
    goes straight into the LLM's context (harness/orchestrator.py), and raw
    float64 noise wastes tokens and risks the model mis-citing digits that
    don't carry real information."""
    return DimensionScore(score=round(score, 2), evidence={k: round(v, 2) for k, v in evidence.items()})
```

每个维度输出两样东西：

- **`score`**：0 到 100 的分数。
- **`evidence`**：证据，是一个字典，放的是计算这个分数用到的原始值，比如 `{"tempo_stability": 0.03, "dynamic_range_db": 24.68, "frequency_balance_std_db": 10.56}`。

**证据是 L4 唯一能引用的数字来源**

第 6 章的系统提示词要求：AI 解读里的每一个数字，都必须来自这里（第 6.4 节）。只输出一个分数，L4 就只能说"物理精确性 77 分"；有了证据，它才能解释"因为拍间隔标准差只有 0.03 秒，节奏很稳"。

**证据使用原始值，不是子分数**

比如动态范围使用的是 24.68 dB，而不是换算后的 0.98。原始值有单位、有物理含义，用户能理解；子分数只是公式的中间结果。

### 四个维度独立展示

四个维度独立展示，不加权合成一个总分。美是多维的。

## 5.2 物理精确性

物理精确性衡量的是声音在物理层面的执行精度：节奏稳不稳、强弱层次够不够、频率分布均不均衡。

```python
TEMPO_STABILITY_UNSTABLE = 0.13  # set so the steadiest real track measured (0.013s) scores ~0.9

DYNAMIC_RANGE_DB_MIN = 5.0
DYNAMIC_RANGE_DB_MAX = 25.0  # widest real dynamic range measured

# std of mean energy across three mel-frequency thirds, in dB — dB is
# gain-invariant, raw mel power isn't (its std scales with loudness).
FREQUENCY_BALANCE_REFERENCE_STD_DB = 25.0

WEIGHTS = {"beat": 0.4, "dynamic": 0.3, "balance": 0.3}


def score_physical_precision(fb: FeatureBundle) -> DimensionScore:
    beat_score = 1.0 - min(fb.tempo_stability / TEMPO_STABILITY_UNSTABLE, 1.0)
    dynamic_score = normalize(fb.dynamic_range_db - DYNAMIC_RANGE_DB_MIN, DYNAMIC_RANGE_DB_MAX - DYNAMIC_RANGE_DB_MIN)

    mel_db = librosa.power_to_db(fb.mel_spectrogram)
    mel_thirds = np.array_split(mel_db.mean(axis=1), 3)
    balance_std_db = float(np.std([third.mean() for third in mel_thirds]))
    balance_score = 1.0 - normalize(balance_std_db, FREQUENCY_BALANCE_REFERENCE_STD_DB)

    score = (beat_score * WEIGHTS["beat"] + dynamic_score * WEIGHTS["dynamic"] + balance_score * WEIGHTS["balance"]) * 100
    return dimension_score(
        score=score,
        evidence={
            "tempo_stability": fb.tempo_stability,
            "dynamic_range_db": fb.dynamic_range_db,
            "frequency_balance_std_db": balance_std_db,
        },
    )
```

这个维度只用到 L1 的结果，三个子指标分别对应 `beat_score`、`dynamic_score`、`balance_score` 三行。

### 节奏稳定性（权重 0.4）

$$\text{beat} = 1 - \min\left(\frac{\text{tempo\_stability}}{0.13},\ 1\right)$$

`tempo_stability` 是拍间隔的标准差（第 3.7 节），越小越稳定，所以要反转。这里用 `min(..., 1.0)` 而不是 `normalize`，效果相同：拍间隔标准差达到 0.13 秒及以上，节奏稳定性得 0 分。

参照值 0.13 秒的定法是：让校准曲目中拍间隔标准差最小的巴赫独奏得到 0.9 分，也就是 $1 - 0.013 / 0.13 = 0.9$。

第 3.7 节说过，`tempo_stability` 有约 0.01 秒的底噪：即使是完全均匀的节拍，也会测出 0.01 秒左右。0.01 秒对应的子分数差异约为 $0.01 / 0.13 \approx 0.08$。

### 动态范围（权重 0.3）

$$\text{dynamic} = \text{normalize}(\text{dynamic\_range\_db} - 5,\ 25 - 5)$$

这是所有子指标里唯一一个先减去下限、再除以区间宽度的：低于 5 dB 计为 0 分，5 到 25 dB 之间线性给分，25 dB 以上满分。比如 15 dB，子分数是 $(15 - 5) / 20 = 0.5$。

这一项使用 L1 输出的 `dynamic_range_db`。L1 先按 RMS 阈值裁剪首尾，再将第 95 与第 5 百分位数的比值换算为分贝（第 3.9 节）。

### 频率均衡度（权重 0.3）

这个子指标衡量低、中、高频的能量是否均衡。计算分四步：

1. `librosa.power_to_db(fb.mel_spectrogram)`：把 L1 的 mel 频谱从功率换成分贝，形状仍然是 `(128, T)`。
2. `mel_db.mean(axis=1)`：每个频带在时间上取平均，得到 128 个数，表示每个频带整首歌的平均能量。
3. `np.array_split(..., 3)`：把 128 个数按顺序分成三组，每组再取平均，得到低、中、高三个数。
4. `np.std(...)`：三个数的标准差，就是 `balance_std_db`。标准差越小，三组越接近，越均衡。

以《Forever Love》为例，三组的平均能量是 -1.05、-11.21、-26.73 dB，标准差是 10.56 dB；`sample.mp3` 是 -16.46、-30.68、-50.18 dB，标准差是 13.82 dB。`sample.mp3` 三组之间的差距更大，所以均衡度更低。

**为什么先换成分贝**

如果直接用功率，同一首歌音量大一倍，每个频带的功率都变成 4 倍，三组之间的标准差也跟着变大，结果会随上传文件的音量变化。换成分贝后，音量变化只是给所有频带加上同一个常数，三组之间的差距不变，标准差也不变（第 2.2.3 节的验证）。

**为什么用 array_split**

128 不能被 3 整除。`np.split` 要求等分，128 分 3 份会直接报错；`np.array_split` 允许不等分，分成 43、43、42 个频带。

**三组是按频带个数分的，不是按 Hz 分的**

按频带中心频率算，三组大约对应：

| 组 | 频带数 | 频率范围 |
|---|---|---|
| 低 | 43 | 约 26 Hz 到 1.1 kHz |
| 中 | 43 | 约 1.1 kHz 到 3.5 kHz |
| 高 | 42 | 约 3.6 kHz 到 10.7 kHz |

因为 mel 刻度低频密、高频疏（第 2.4.1 节），"低频"这一组覆盖到了 1.1 kHz，比日常说的"低音"宽得多：人声和大部分乐器的基频都在这一组里。

参照值 25 dB 的来源：初始校准组的观测值在 8.8 到 14.2 dB 之间，跨度很窄，参照值在此基础上从 20 dB 适度放宽到 25 dB。

### 物理精确性的计算示例

**《Forever Love》**

证据值：拍间隔标准差 0.03 秒，动态范围 24.68 dB，频率均衡 10.56 dB。

$$
\begin{aligned}
\text{beat} &= 1 - 0.03 / 0.13 = 0.769 \\
\text{dynamic} &= (24.68 - 5) / 20 = 0.984 \\
\text{balance} &= 1 - 10.56 / 25 = 0.578 \\
\text{score} &\approx (0.4 \times 0.769 + 0.3 \times 0.984 + 0.3 \times 0.578) \times 100 = 77.6
\end{aligned}
$$

以上按展示的证据值估算。系统先用原始精度计算分数，再分别将分数和证据四舍五入到两位小数。

**`sample.mp3`**

展示的证据值为 0.03 秒、11.87 dB 和 13.82 dB。复算时，拍间隔标准差取约 0.0282 秒，保留更多有效数字。

$$
\begin{aligned}
\text{beat} &= 1 - 0.0282 / 0.13 \approx 0.783 \\
\text{dynamic} &= (11.87 - 5) / 20 \approx 0.344 \\
\text{balance} &= 1 - 13.82 / 25 \approx 0.447 \\
\text{score} &\approx (0.4 \times 0.783 + 0.3 \times 0.344 + 0.3 \times 0.447) \times 100 = 55.05
\end{aligned}
$$

这首咏叹调节奏很稳，但强弱变化小，三组频带差距大，后两项把分数拉了下来。

### 编制与自由速度对得分的影响

这个维度对"安静、独奏、编制稀疏"的作品不友好，主要来自频率均衡度。独奏小提琴的能量天然集中在中高频的一个窄频段里，和全编制的混音相比，三组频带的差距更大，均衡度得分更低。但这是乐器本身的音色，不是演奏或制作的缺陷。

节奏稳定性也有类似的问题。《Art of Life》这类作品有大量的速度自由处理（rubato），这是一种表现手法，在这个指标上却会被扣分。

这些得分反映了作品的拍间隔变化和频带能量分布。自由速度的表达效果和独奏音色的特点还要结合作品理解。第 6.4 节的系统提示词要求按指标实际测量的内容解读分数。

## 5.3 结构逻辑

结构逻辑衡量的是和声与段落的组织：和声用得规不规范，段落安排得整不整齐，用了多少种和声素材。

```python
SEGMENT_BALANCE_RATIO_MAX = 2.0
CHORD_VOCABULARY_SIZE = 24.0

WEIGHTS = {"tsd_coverage": 0.3, "segment_balance": 0.3, "chord_variety": 0.4}


def score_structural_logic(fb: FeatureBundle, ub: UnderstandingBundle) -> DimensionScore:
    tsd_coverage = calc_tsd_coverage(ub.chords, fb.key)

    seg_durations = [s.end_sec - s.start_sec for s in ub.structure]
    mean_duration = float(np.mean(seg_durations))
    std_duration = float(np.std(seg_durations))
    balance_ratio = std_duration / mean_duration if mean_duration > 0 else 0.0
    balance_score = 1.0 - normalize(balance_ratio, SEGMENT_BALANCE_RATIO_MAX)

    n_distinct_chords = len({c.chord for c in ub.chords})
    chord_variety_score = normalize(n_distinct_chords, CHORD_VOCABULARY_SIZE)

    score = (
        tsd_coverage * WEIGHTS["tsd_coverage"] + balance_score * WEIGHTS["segment_balance"] + chord_variety_score * WEIGHTS["chord_variety"]
    ) * 100
    return dimension_score(
        score=score,
        evidence={
            "tsd_coverage": tsd_coverage,
            "segment_balance_ratio": balance_ratio,
            "n_distinct_chords": n_distinct_chords,
        },
    )
```

三个子指标分别用到 L1 的调性和 L2 的和弦（覆盖率），L2 的段落（均衡度），L2 的和弦（丰富度）。

### T-S-D 覆盖率（权重 0.3）

覆盖率回答的是：识别出的和弦里，有多大比例属于这首歌所在调的主、下属、属三种功能（第 2.1.2 节）。T、S、D 是 Tonic、Subdominant、Dominant 的首字母。和弦清单怎么选、代码怎么生成，第 2.1.2 节已经逐项讲过，这里按计算顺序把三步串起来。

**第一步:把调和和弦都换成"音级 + 种类"**

```python
def _parse_chord(chord: str) -> tuple[int, str] | None:
    """Parses classifiers/chord.py's "G"/"Gm" style labels into (pitch_class, quality)."""
    root, quality = (chord[:-1], "min") if chord.endswith("m") else (chord, "maj")
    pitch_class = NOTE_TO_PITCH_CLASS.get(root)
    return None if pitch_class is None else (pitch_class, quality)


def _parse_key(key: str) -> tuple[int, str] | None:
    """Parses features/harmonic.py's "D minor"/"C major" into (pitch_class, mode)."""
    root, _, mode = key.partition(" ")
    pitch_class = NOTE_TO_PITCH_CLASS.get(root)
    return None if pitch_class is None else (pitch_class, mode)
```

- `_parse_chord`：和弦名以 `m` 结尾的是小三和弦，去掉 `m` 剩下的是根音；否则是大三和弦，整个字符串就是根音。`"Gm"` 变成 `(7, "min")`，`"F#"` 变成 `(6, "maj")`。
- `_parse_key`：调性按空格拆成主音和调式。`"Eb major"` 变成 `(3, "major")`。
- 两个函数都用 `NOTE_TO_PITCH_CLASS` 把音名换成 0 到 11 的整数。查不到的音名返回 `None`。

调性来自 Essentia（第 3.8 节），和弦来自 madmom（第 4.5 节），两个库对升降号的写法不一致：Essentia 会输出 `"Eb major"`，madmom 只用升号，同一个音写成 `D#`。换成整数后再比较，`D#` 和 `Eb` 都是 3，就不会出现"主和弦不属于这个调"的错误（第 2.1.1 节）。

**第二步:根据调生成和弦清单**

`_tsd_chords` 按"离主音几个半音 + 和弦种类"生成清单（第 2.1.2 节）：

| 调式 | 主功能 | 下属功能 | 属功能 |
|---|---|---|---|
| 大调 | I、vi | IV、ii | V |
| 小调 | i、III | iv、VI | v、V |

没有收录的自然和弦有三类：减三和弦（madmom 的词表里没有）、大调的 iii 和小调的 VII（功能归属不明确）。小调同时收录 v 和 V：自然小调的第 5 级是小三和弦，和声小调把导音升高后变成大三和弦，两种在真实音乐里都很常见。

**第三步:计算比例**

```python
def calc_tsd_coverage(chords: list[ChordEvent], key: str) -> float:
    if not chords:
        return 0.0
    parsed_key = _parse_key(key)
    if parsed_key is None:
        return 0.0
    tsd_set = _tsd_chords(*parsed_key)
    matches = sum(1 for c in chords if _parse_chord(c.chord) in tsd_set)
    return matches / len(chords)
```

落在清单里的和弦事件数，除以和弦事件总数。没有识别出任何和弦，或者调性解析不出来，覆盖率记为 0。

两点需要注意：

- **按事件个数算，不是按时长算。** 一个持续 10 秒的和弦和一个持续 1 秒的和弦，各算一次。
- **覆盖率本身就在 0 到 1 之间**，不需要再除以参照值，直接作为子分数。

以 `sample.mp3` 为例：调性是 G 大调，清单是 G、Em、C、Am、D。12 个和弦事件里，G 出现 2 次、D 出现 4 次、Em 出现 2 次、C 出现 1 次，一共 9 个落在清单里；F#m、F#、A 各 1 次，不在清单里。覆盖率是 $9 / 12 = 0.75$。

### 段落均衡度（权重 0.3）

$$\text{segment\_balance} = 1 - \text{normalize}\left(\frac{\sigma_{\text{段落时长}}}{\mu_{\text{段落时长}}},\ 2.0\right)$$

先算出每个段落的时长，再算它们的标准差除以平均值，也就是变异系数（第 2.9.1 节）。变异系数越小，各段越接近，越均匀，所以反转。

用变异系数而不是标准差，是因为它和歌曲长短无关。例如，20、40、20、40 秒的四个段落共 2 分钟，标准差是 10 秒。把每段放大到原来的 10 倍，总时长是 20 分钟，标准差变成 100 秒。两组段落的平均时长也相差 10 倍，变异系数都约为 0.33。

**为什么要截断**

当段落长短差异很大时，变异系数可能超过参照值 2.0。例如，五段各 1 秒、一段 200 秒，变异系数约为 2.17。若直接用 $1-2.17/2.0$ 计分，这一项会得到负值。代码先把比例截断到 0 至 1，再反向计分。

> 第 1 章引用的 AI 解读，把"段落长度均衡比 0.41"解释成"越接近 1 越均匀"，方向正好说反了。这个数是变异系数，越小越均匀。第 6 章会讨论这类误读。

### 和弦丰富度（权重 0.4）

```python
n_distinct_chords = len({c.chord for c in ub.chords})
chord_variety_score = normalize(n_distinct_chords, CHORD_VOCABULARY_SIZE)
```

`{c.chord for c in ub.chords}` 是一个集合，重复的和弦名只保留一个，集合的大小就是这首歌用了多少种不同的和弦。除以 24 得到子分数。`sample.mp3` 用了 G、F#m、D、Em、C、F#、A 共 7 种，子分数是 $7 / 24 = 0.29$。

**这个子指标是后来加上的**

最初结构逻辑只有前两个子指标，各占一半权重。在测试组的歌曲里出现了这样的排序：

| 曲目 | 结构逻辑（只有前两个子指标） |
|---|---|
| 生日快乐 | 82.7 |
| Forever Love | 81.7 |
| Art of Life | 61.1 |

《生日快乐》只用了 F、A#、C 三个和弦，正好是 I、IV、V，覆盖率天然满分；段落短而整齐，均衡度也高。《Art of Life》用了 21 种不同的和弦，中途大量转调，覆盖率反而低。前两个子指标只衡量"规不规范"，完全没有衡量"用了多少和声素材"。

加入和弦丰富度时，有两个设计选择：

- **用种类数，不用"种类数 ÷ 事件数"。** 比值看起来更公平，但它会随歌曲变长而变小：长曲目里同样几种和弦会重复很多次，事件数变大，比值被稀释。《Art of Life》有 620 个和弦事件、21 种和弦，比值约 0.03；《生日快乐》3 种和弦、事件数很少，比值反而更高，和直觉完全相反。

- **不加"段落数量"。** 当时也考虑过把段落数当作结构复杂度的指标。但段落数和歌曲时长有关，越长的歌分出的段落天然越多，加进来会系统性地奖励长曲目，所以没有加。

权重调整为 0.3、0.3、0.4，丰富度占的比重最大。结果是：《生日快乐》从 82.7 降到 54.6，《Art of Life》从 61.1 升到 71.6，《Forever Love》75.7，排序变得符合直觉。

### 结构规范性与和弦多样性

覆盖率和均衡度奖励的是"规范"：用的是调内的核心和弦，段落长度整齐。丰富度奖励的是"多样"：用了更多种和弦。

- 只有规范，简单的儿歌会得高分。
- 只有多样，杂乱无章的和弦堆砌也会得高分。

两类子指标放在一起，结构逻辑衡量的是"在规范的框架里，用了多少素材"。

即便如此，这个维度本质上仍然偏向"常规"。在测试组的歌曲里，巴赫十二平均律前奏曲的覆盖率是 0.853，一首 Lofi Hip Hop 是 0.812，两者很接近。这大概率是真实的：Lofi 常见的做法就是循环一段简单的爵士和弦进行，本身就很"调性正统"。先锋的和声、自由的曲式，在这个维度上会得低分。

覆盖率还有一个容易忽略的假设：整首歌只按一个调计算。《Art of Life》中途多次转调，转调之后的和弦按原来的调去对照清单，大多不在清单里，覆盖率只有 0.535。这不是计算错误，而是"一首歌只有一个调"这个简化带来的结果。

### 结构逻辑的计算示例

**《Forever Love》**

证据值：覆盖率 0.84，段落时长变异系数 0.41，16 种不同的和弦。

$$
\begin{aligned}
\text{tsd} &= 0.84 \\
\text{segment\_balance} &= 1 - 0.41 / 2 = 0.795 \\
\text{chord\_variety} &= 16 / 24 = 0.667 \\
\text{score} &\approx (0.3 \times 0.84 + 0.3 \times 0.795 + 0.4 \times 0.667) \times 100 = 75.7
\end{aligned}
$$

按展示的证据值估算约为 75.7 分。全曲识别出 174 个和弦事件，其中 146 个对应清单中的主、下属或属功能和弦，因此覆盖率约为 0.84。结构分段共得到 20 个段落。

**`sample.mp3`**

这段音频有 12 个和弦事件，其中 9 个匹配和声功能清单，共识别出 7 种和弦。根据第 4 章的分析结果，两段分别长 1.76 秒和 28.24 秒，段落时长的变异系数约为 0.8827。

$$
\begin{aligned}
\text{tsd} &= 9 / 12 = 0.75 \\
\text{segment\_balance} &= 1 - 0.8827 / 2 \approx 0.559 \\
\text{chord\_variety} &= 7 / 24 \approx 0.292 \\
\text{score} &\approx \left(0.3 \times 0.75 + 0.3 \times (1 - 0.8827 / 2) + 0.4 \times \frac{7}{24}\right) \times 100 \approx 50.93
\end{aligned}
$$

两段的时长差距较大，拉低了段落均衡度。接口显示的变异系数是 0.88，计分使用四舍五入前的值。

## 5.4 情感深度

情感深度衡量的是情感弧线（第 4.2 节）本身的起伏：情绪变化的幅度有多大，转折有多频繁。

它不衡量"情绪是否强烈"。一首从头到尾都很悲伤的歌，弧线是平的，在这个维度上得分很低。

```python
VALENCE_DELTA_MAX = 1.0
AROUSAL_STD_MAX = 0.15
POLARITY_HYSTERESIS = 0.12
POLARITY_SWITCH_RATE_REFERENCE = 0.025

WEIGHTS = {"valence_delta": 0.4, "arousal_std": 0.3, "polarity_switch_rate": 0.3}


def score_emotional_depth(ub: UnderstandingBundle) -> DimensionScore:
    valence = [p.valence for p in ub.emotion_arc]
    arousal = [p.arousal for p in ub.emotion_arc]

    valence_delta = max(valence) - min(valence)
    arousal_std = float(np.std(arousal))
    polarity_switches = _count_polarity_switches(valence)
    polarity_switch_rate = polarity_switches / (len(valence) - 1) if len(valence) > 1 else 0.0

    valence_score = normalize(valence_delta, VALENCE_DELTA_MAX)
    arousal_score = normalize(arousal_std, AROUSAL_STD_MAX)
    polarity_score = normalize(polarity_switch_rate, POLARITY_SWITCH_RATE_REFERENCE)

    score = (
        valence_score * WEIGHTS["valence_delta"] + arousal_score * WEIGHTS["arousal_std"] + polarity_score * WEIGHTS["polarity_switch_rate"]
    ) * 100
    return dimension_score(
        score=score,
        evidence={
            "valence_delta": valence_delta,
            "arousal_std": arousal_std,
            "polarity_switches": polarity_switches,
            "polarity_switch_rate": polarity_switch_rate,
        },
    )
```

这个维度只用到 L2 的情感弧线：先把弧线上每个点的效价、唤醒度分别取出来，变成两个列表，再算三个子指标。

### 效价落差（权重 0.4）

弧线上效价的最大值减最小值，除以参照值 1.0。它衡量的是情绪在正面和负面之间走了多远。《Art of Life》在校准时的效价落差约为 0.92，对应的子分数约为 0.92。

### 唤醒度标准差（权重 0.3）

唤醒度的标准差，除以参照值 0.15。它衡量的是激动程度起伏有多大。《Art of Life》在校准时的唤醒度标准差为 0.135，对应的子分数为 0.90。

### 极性切换率（权重 0.3）

极性切换率衡量情感弧线上的效价在正、负两种状态之间切换得有多频繁。代码逐个读取效价值。低于 `-0.12` 记为负状态，高于 `0.12` 记为正状态，两者之间的值（含端点）保持上一次的状态。第一次进入正或负状态只确定起点。此后每次从一种状态进入另一种状态，计为一次切换（第 2.9.3 节）。

例如，效价依次为 `[-0.20, -0.04, 0.06, 0.18]`。第一个值建立负状态，中间两个值都在阈值范围内，直到最后一个值才切换为正状态，因此共计一次。

```python
POLARITY_HYSTERESIS = 0.12


def _count_polarity_switches(valence: list[float]) -> int:
    state = None
    switches = 0
    for v in valence:
        if v > POLARITY_HYSTERESIS:
            if state == "neg":
                switches += 1
            state = "pos"
        elif v < -POLARITY_HYSTERESIS:
            if state == "pos":
                switches += 1
            state = "neg"
    return switches
```

阈值 `0.12` 取自《G 弦上的咏叹调》的效价曲线。该曲相邻效价值之差的标准差约为 `0.060`，项目取其两倍作为缓冲范围的半宽，以减少零点附近的小幅波动被计作切换。

切换率等于切换次数除以相邻点的间隔数。弧线上有 $N$ 个点，就有 $N-1$ 个间隔。点数少于两个时，切换率记为 0。将次数按间隔数换算，可以比较时长不同的曲目（第 2.9.4 节）。

评分时，将切换率除以参照值 `0.025`，把结果限制在 0 到 1，再按 30% 的权重计入情感深度。证据字段同时保留切换次数和切换率。

### 情感深度的计算示例

**《Forever Love》**

证据值：效价落差 0.67，唤醒度标准差 0.05，切换率 0.02（切换 8 次）。

$$
\begin{aligned}
\text{valence} &= 0.67 / 1.0 = 0.67 \\
\text{arousal} &= 0.05 / 0.15 = 0.333 \\
\text{polarity} &= 0.02 / 0.025 = 0.8 \\
\text{score} &\approx (0.4 \times 0.67 + 0.3 \times 0.333 + 0.3 \times 0.8) \times 100 = 60.8
\end{aligned}
$$

切换率显示为 0.02，实际计算保留更多小数。参照值为 0.025，这一步的精度会明显影响复算出的子分数。

**`sample.mp3`**

证据值：效价落差 0.16，唤醒度标准差 0.02，切换率 0（切换 0 次）。

$$
\begin{aligned}
\text{valence} &= 0.16 / 1.0 = 0.16 \\
\text{arousal} &= 0.02 / 0.15 \approx 0.133 \\
\text{polarity} &= 0 / 0.025 = 0 \\
\text{score} &= \left(0.4 \times 0.16 + 0.3 \times \frac{0.02}{0.15} + 0.3 \times 0\right) \times 100 = 10.40
\end{aligned}
$$

### 响度与节奏密度对情感深度得分的影响

这个维度把效价和唤醒度的变化当作情绪的起伏。但唤醒度上升不一定来自情绪本身。EDM 里常见的"渐强—爆发"段落，唤醒度会大幅上升，主要是因为响度和节奏密度在增加，而不是情感叙事有什么变化。这类作品可能在情感深度上得到高分，但这个高分并不代表和声或旋律上的深度。

下表列出 EDM 测试中的观测结果。

| 曲目                                          | 风格                        | 物理精确性 | 情感深度 |
| ------------------------------------------- | ------------------------- | ----- | ---- |
| deadmau5《Ghosts 'n' Stuff》                  | 纯机械循环                     | 92.6  | 23.5 |
| Daft Punk《Harder, Better, Faster, Stronger》 | 完整编曲弧线 + vocoder 人声旋律     | —     | 84.6 |
| Charlotte de Witte《One Mind》                | techno，有 build-up/drop 段落 | —     | 74.4 |

deadmau5 的循环曲目符合"物理精确性高、情感深度低"的预期。《One Mind》和 Daft Punk 曲目的情感深度偏高：techno 的 build-up 让唤醒度大幅上升。在效价—唤醒模型里，这是真实的情绪变化，不是模型噪声；但它来自能量的堆叠，而不是旋律或和声推动的情感叙事。

## 5.5 活力张力

活力张力用段落之间的强弱对比和起音活动的密集程度，描述音乐的能量起伏与推动感。

```python
DYNAMIC_CONTRAST_MAX = 0.29  # widest real segment-to-segment contrast measured

WEIGHTS = {"dynamic_contrast": 0.5, "burst_density": 0.5}


def score_vital_tension(fb: FeatureBundle, ub: UnderstandingBundle) -> DimensionScore:
    dynamic_contrast = _segment_dynamic_contrast(fb, ub)
    dynamic_score = normalize(dynamic_contrast, DYNAMIC_CONTRAST_MAX)

    burst_density = onset_burst_density(fb.onset_strength, fb.sample_rate, fb.duration_sec)
    burst_score = normalize(burst_density, BURST_DENSITY_REFERENCE_PER_MIN)

    score = (dynamic_score * WEIGHTS["dynamic_contrast"] + burst_score * WEIGHTS["burst_density"]) * 100
    return dimension_score(
        score=score,
        evidence={
            "dynamic_contrast": dynamic_contrast,
            "burst_density": burst_density,
        },
    )
```

两个子指标各占一半。这个维度同时用到 L1 的时间序列和 L2 的段落边界。

### 跨段落动态对比（权重 0.5）

```python
def _segment_dynamic_contrast(fb: FeatureBundle, ub: UnderstandingBundle) -> float:
    frame_times = np.arange(len(fb.rms)) * HOP_LENGTH / fb.sample_rate
    segment_means = []
    for seg in ub.structure:
        mask = (frame_times >= seg.start_sec) & (frame_times < seg.end_sec)
        if mask.any():
            segment_means.append(float(fb.rms[mask].mean()))
    return max(segment_means) - min(segment_means) if len(segment_means) > 1 else 0.0
```

这段代码要把两个不同来源的数据对齐：L1 的 RMS 是按帧排列的，L2 的段落边界是基于秒的。

1. `frame_times`：用 $i \times 512 / 22050$ 算出每一帧对应的秒数（第 2.3.2 节）。`np.arange(len(fb.rms))` 是 0、1、2……一直到最后一帧的编号。
2. 对每个段落，`mask` 是一个和 RMS 一样长的布尔数组：这一帧的时间落在段落范围内是 True，否则是 False。`fb.rms[mask]` 只取出 True 的那些帧，再求平均，就是这个段落的平均响度。`mask.any()` 检查这个段落里至少有一帧，避免对空数组求平均。
3. 所有段落的平均响度里，最大的减去最小的，就是动态对比。只有一个段落时，记为 0。

校准曲目中，《Forever Love》的跨段落动态对比最高，为 0.259。将这一观测值对应到约 0.9，得到参照值 $0.259 / 0.9 \approx 0.29$（第 5.1 节）。

**为什么不用整首歌的 RMS 最大值减最小值**

原因是逐帧的最大最小值测的是"哪一瞬间最响、哪一瞬间最轻"。只要某一帧特别响、某一帧特别轻，结果就会很大，不管这两帧在歌曲结构里处于什么位置。逐帧极差混淆了"制作上的瞬间响度起伏"和"结构上从安静走到爆发"这两件事。

这个指标和第 2.2.3 节介绍的响度统计都利用一段时间内的数据。这里计算的是结构段落内的平均 RMS，最终取各段均值的极差。

项目为此写了一个测试：构造两组合成的 RMS 数据，一组是真实的"安静段落 → 响亮段落"，另一组帧与帧之间抖动很大、但段落之间没有强弱差别。断言前者的动态对比更高。

### 起音爆发密度（权重 0.5）

和 L2 的能量感（第 4.8 节）是同一个函数、同一个参照值 310，都从 L1 的 `features/dynamic.py` 引用（第 3.10 节）。

### 活力张力的计算示例

**《Forever Love》**

证据值：动态对比 0.26，爆发密度每分钟 279 次。

$$
\begin{aligned}
\text{dynamic} &= 0.26 / 0.29 = 0.897 \\
\text{burst} &= 279 / 310 = 0.900 \\
\text{score} &\approx (0.5 \times 0.897 + 0.5 \times 0.900) \times 100 = 89.8
\end{aligned}
$$

**`sample.mp3`**

根据第 4 章示例的分段边界复算，动态对比约为 0.02527，显示为 0.03。爆发密度为每分钟 216 个峰值。

$$
\begin{aligned}
\text{dynamic} &= 0.02527 / 0.29 \approx 0.087 \\
\text{burst} &= 216 / 310 \approx 0.697 \\
\text{score} &\approx \left(0.5 \times \frac{0.02527}{0.29} + 0.5 \times \frac{216}{310}\right) \times 100 \approx 39.2
\end{aligned}
$$

两段的平均 RMS 接近，因此39.2 分中，大部分来自起音爆发密度。

### 段内渐强对跨段落动态对比的影响

和物理精确性一样，这个维度偏向全编制、强弱对比鲜明的作品。

在测试组的歌曲里，《G 弦上的咏叹调》活力张力只有 23.3 分，是最低的。起初怀疑是弦乐的起音不清晰、检测失效，但把原始数据打出来看，288 秒里检测到 544 个峰，每分钟 113 次，检测是正常的。真正拉低分数的是动态对比，只有 0.029：这首曲子从头到尾每一段的平均响度都很接近。这是真实的音乐特征：它是一条连续、克制的旋律线，不靠强弱对比制造张力。

还有一种情况这个指标测不到。肖邦夜曲 Op.9 No.2 的动态对比只有 0.037，但其中一个段落内部有一次戏剧性的渐强，段内的峰值是其他段落峰值的两三倍。因为渐强发生在一个段落内部，被段落平均值抹平了。

## 5.6 本章小结

L3 根据 L1 的声学特征和 L2 的音乐理解结果，分别计算物理精确性、结构逻辑、情感深度和活力张力。每个维度先把各项指标换算成 0 到 1 的子分数，再按权重合成百分制得分。系统同时保留拍间隔标准差、极性切换次数等证据值，供下一章的 L4 解读使用。

理解分数要回到指标的定义。例如，跨段落动态对比比较的是各段的平均 RMS。如果一首曲子在某个段落内有明显的渐强，但各段的平均 RMS 接近，这项得分仍可能偏低。四维分数与听众判断是否一致，仍需通过听众评价验证。
